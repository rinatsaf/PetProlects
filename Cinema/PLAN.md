# PLAN

## Назначение

Этот файл нужен как рабочий roadmap по проекту `Cinema`: что уже есть, что нужно доделать и в каком порядке идти дальше.

## Текущее состояние

По коду сейчас уже есть:

- слоистая архитектура `Api / Application / Domain / Infrastructure`;
- базовая модель данных;
- репозитории и сервисный слой;
- cookie-based аутентификация и роли;
- резервирование мест через Redis;
- платежный сценарий через YooKassa;
- фоновая очистка просроченных заказов.

Пока не реализованы или не доведены до конца:

- frontend;
- SignalR для realtime-обновления мест;
- JWT/refresh token flow;
- email-отправка билетов;
- генерация PDF/QR билетов;
- рекомендации и персонализированная выдача;
- health checks, наблюдаемость и интеграционные тесты;
- полноценная админка.

## Актуальный план развития

### 1. Довести базовый backend до законченного состояния

Что сделать:

- закрыть CRUD-сценарии по фильмам, жанрам, залам, сеансам, заказам и билетам;
- проверить авторизацию на `PUT`/`DELETE` endpoints;
- привести ошибки API к единому формату;
- дописать конфигурацию `appsettings` и описание запуска.

Результат:

- backend становится цельным и предсказуемым.

### 2. Доделать сценарий бронирования мест

Что сделать:

- добавить endpoint'ы `hold`, `renew hold`, `release hold`;
- синхронизировать жизненный цикл `Order`, `Ticket` и Redis-hold;
- защитить сценарий от повторной оплаты и конфликтов;
- добавить тесты на конкурентное бронирование мест.

Результат:

- процесс бронирования становится надёжным и демонстрируемым.

### 3. Завершить платежный контур

Что сделать:

- ограничить ручное изменение статуса платежа;
- проверить идемпотентность webhook'ов;
- зафиксировать допустимые переходы статусов `Order`, `Payment`, `Ticket`;
- оформить локальный сценарий тестирования через `ngrok`.

Результат:

- платёжный сценарий становится устойчивым.

### 4. Реализовать ранжирование интересов пользователя

Это один из лучших следующих шагов, потому что основа в модели данных уже есть: `UserInteraction` и `UserPreference`.

Что сделать:

- писать пользовательские действия в `UserInteraction`;
- добавить веса действий:
  - `View` = 1
  - `OpenDetails` = 2
  - `CreateOrder` = 4
  - `BuyTicket` = 6
- агрегировать интересы пользователя в `UserPreference`;
- учитывать интересы не только по фильму, но и по признакам:
  - жанр;
  - время сеанса;
  - диапазон цены;
  - тип зала;
- сделать сервис ранжирования предложений по score;
- добавить endpoint рекомендаций:
  - `GET /api/movies/recommendations`
  - или `GET /api/sessions/recommendations`

Результат:

- пользователь будет видеть более релевантные фильмы и сеансы.

Практический порядок реализации:

1. Логировать действия в `UserInteraction`.
2. Реализовать пересчёт `UserPreference`.
3. Сделать простой score-based ranking без ML.
4. Отдать рекомендации через API.

### 5. Добавить realtime для мест в зале

Что сделать:

- добавить SignalR Hub;
- отправлять события `hold/release/sold`;
- подготовить контракт под будущий frontend.

Результат:

- бронь мест обновляется в реальном времени.

### 6. Добавить доставку билетов после оплаты

Что сделать:

- генерация кода билета и QR;
- отправка email после оплаты;
- повторные попытки отправки при сбоях;
- хранение технической информации об отправке.

Результат:

- сценарий покупки становится завершённым.

### 7. Улучшить безопасность и эксплуатацию

Что сделать:

- решить, остаётся ли cookie auth или нужен JWT;
- добавить rate limiting на чувствительные endpoints;
- вынести секреты из локальных конфигов;
- добавить health checks для PostgreSQL и Redis;
- написать интеграционные тесты на ключевые сценарии.

Результат:

- проект становится ближе к production-подходу.

## Приоритет следующей работы

Если идти без распыления, то следующий backlog такой:

1. Дочистить авторизацию и валидацию текущих endpoint'ов.
2. Завершить сценарий `hold -> order -> payment -> webhook -> ticket`.
3. Добавить логирование действий в `UserInteraction`.
4. Реализовать пересчёт `UserPreference`.
5. Сделать endpoint рекомендаций.
6. После этого переходить к SignalR и frontend.

## Минимальная версия рекомендации

Первая версия должна быть простой:

- копить веса интереса по жанрам;
- увеличивать вес после просмотра карточки фильма, заказа и покупки;
- сортировать фильмы по сумме весов жанров;
- если пользователь новый, отдавать популярные или ближайшие сеансы.

Этого достаточно, чтобы показать персонализацию без лишнего усложнения.
